## 0. Extraction conventions and caveats

The scan is OCR-degraded. This file normalizes the notation while keeping the report's own meta-notation:

- `::=` — production
- `{A | B | C}` — one of the alternatives **must** appear (mandatory choice)
- `[A | B]` — optional (may appear or be omitted)
- `X•••` — one or more repetitions of `X`
- `{,• X•••}` — one or more repetitions of `X`, each preceded by `,` (comma-separated list)
- `{.• X•••}` — ditto with `.` (dot-joined, used for name qualification)

Notation variables are lowercase hyphenated names; notation constants are PL/I keywords (uppercase) and symbols. Words printed in production rules *not* separated by whitespace compose single notation constants (e.g. `PROCEDURE` is one word, `GO TO` is two).

Legibility markers:

- ⚠ = OCR of this rule was partially illegible; reconstruction is best-effort, sometimes inferred from context. Details in the rule's footnote.
- Semicolons `;` at statement ends were restored on rules where the OCR dropped them; their presence is confirmed by rules that preserved them (EXIT, STOP, CALL, record-I/O, `SYSTEM ;`) and by the multiple-closure prose ("between 'END' and ';'").
- `¬` is the PL/I not-prefix. The OCR renders it as `,` / `-.` / `=f` / `•` in various places (confirmed by §2.3.3 where `¬ ::= NOT`).
- Original rule numbers `(1)`–`(151)` are preserved for cross-referencing with the printed report.

## 1. Notation semantics (report §2.1)

Given `V ::= S1 T1 | S2 T2 | … | Sn Tn`, the extended forms are:

1. `V ::= {T1 | T2 | … | Tn} S` — mandatory choice (may also be used with n = 1).
   Example: `goto-statement ::= { GOTO | GO TO } reference ;`
2. `V ::= S1 [T1 | … | Tn] S2` — optional.
   Example: `return-statement ::= RETURN [ ( expression ) ]`
3. `V ::= U•••` — one or more repetitions of `U` (recursive closure).
   Example: `integer ::= digit•••`
4. `V ::= S1 T1 [ {T2 | … }••• ] S2` — optional repetition.

Comma-dot form: `V ::= {,• X•••}` stands for `X ( , X )•••`.
Example: `declarationlist ::= {,• declaration•••}` for `DECLARE A, B, C;`.

### Meta-syntax of the notation itself (report §2.2, condensed)

```
<prod-rule> ::= <not-var> <definition>
<definition> ::= <sequence> | <sequence> | <definition>
<sequence>   ::= <unit> <sequence> | <unit>
<unit>       ::= <not-var> | { <definition> } | [ <definition> ] | <unit>••• | <not-const>
<not-var>    ::= <sm-letter> <not-var> | <sm-letter> - <not-var> | <sm-letter>
<not-const>  ::= <PL/I-symbol> <not-const> | <PL/I-symbol>
```

Notation variables are sequences of small letters and hyphens; notation constants are PL/I symbols.

## 2. Generation of a concrete program text (report §2.3.1)

An implementation must provide production rules for the three implementation-dependent notation variables: `external-option`, `io-option`, `extralingual-character`. Generation proceeds in four steps:

1. Replace from `program` using the higher-level rules (§3.1). Continues until no higher-level rule is applicable. Result: a text of "PL/I words" (§5). Words not separated by whitespace compose single notation constants.
2. Insert `space` between adjacent non-delimiters (mandatory); optionally elsewhere, including after the last word. The 24 delimiter words are:
   `( ) , . : ; = + - * / ** || & | ¬ < > >= <= ¬> ¬< ¬= ->`
   (⚠ OCR of the delimiter list partially legible; quote-handling for `'` not fully recoverable.) All other words are non-delimiters. `space` rules are (149).
3. Replace keywords — possibly by their abbreviations (§3.1 of this file) — then apply the lower-level rules (§3.2).
4. Split all notation constants into their single symbols. Result: a text of the 60-character PL/I alphabet, composed of **29 alphabetic characters** (`A–Z` plus the extenders `$ # @`), **10 digits**, and **21 special characters**:
   `blank = + - * / ( ) , . ' : ; & | ¬ > < % _ ?`
   (⚠ the printed list is partially legible; the set above is reconciled with
   C28-8201-1 §60-Character Set, which states the 29 / 10 / 21 composition and
   notes that `?` "has no specific use in the language, even though it is
   included in the 60-character set". Note that `$ # @` are *alphabetic*, not
   special, characters — rule (131) — and that the break character `_` is both
   a special character and an `alphanumeric-character` by rule (132). PL/I's
   quotation mark is the single quote `'`; the double quote is **not** in the
   character set.)

### 3.2 Multiple closure of blocks and groups (report §2.3.2.2)

After the four generation steps (including abbreviations), a part of the program text is a *compound* if it could have been generated by:

```
compound     ::= compoundhead [ compound ] compoundend
compoundhead ::= [ prefixlist ] { [ labellist ] BEGIN [ OPTIONS ( {,• external-option•••} ) ]
               | entry-namelist { PROC | PROCEDURE } [ parameterlist ]
               | [ labellist ] DO [ do-specification | WHILE ( expression ) ] }
               [ sentence••• ]
compoundend  ::= [ prefixlist ] [ labellist ] END [ procedure-optionslist ] ;    ⚠
```

⚠ `compoundend`: the scan prints `[ procedure-optionslist ]` after `END`; the intended placement (after `[parameterlist]` in the procedure alternative, mirroring rule 2) is possible. Verify against print.

Before the rightmost semicolon of a compound (between `END` and `;`), one identifier of the `labellist` or `entry-namelist` of the appertaining compoundhead may be inserted (`END identifier;`).

If a compound has such a compoundend (`END identifier;`) where `identifier` does **not** occur in the labellist/entry-namelist of its compoundhead, an immediately preceding compoundend with no prefix- or labellist may be omitted.

### 3.3 Programs in the 48-character set (report §2.3.3)

The 48-character set is the 60-character set (§2) less twelve characters:
`A–Z $ 0–9 blank = + - * / ( ) , . '` — i.e. 27 alphabetic characters (the 26
letters and `$`), 10 digits, and 11 special characters.

1. From the rules for `letter`, `alphanumeric-character`, `string-character`,
   `comment-symbol`, the following 12 symbols must be deleted:
   `@ # : ; & | ¬ < > % _ ?`
   *Cross-check:* C28-8201-1 §48-Character Set — "The 48-character set is
   composed of 48 characters of the 60-character set. In all but four cases,
   the characters of the reduced set can be combined to represent the missing
   characters… The four characters that are not duplicated are the commercial
   'at' sign, the number sign, the break character, and the question mark."
   That fixes `@ # _ ?` as the four without substitutes; the remaining eight
   (`: ; & | ¬ < > %`) are the ones given replacements below. 60 − 12 = 48
   reconciles exactly.
2. The following **13** PL/I words are handled as notation variables and
   replaced by the (higher level) production rules:

   | Word | Replacement | Word | Replacement |
   |---|---|---|---|
   | `;` | `,.` | `<=` | LE |
   | `¬` | NOT | `¬>` | NG |
   | `&` | AND | `¬<` | NL |
   | `\|` | OR | `¬=` | NE |
   | `>` | GT | `\|\|` | CAT |
   | `<` | LT | `->` | PT |
   | `>=` | GE | | |

   *Cross-check:* this resolves the report's "13 words" against the 12 letter
   sequences of rule 3 below: the thirteenth word is the **semicolon**, whose
   replacement is `,.` (comma-period), not a letter sequence. C28-8201-1's
   composite-symbol table lists precisely `,.` ↔ `;`, `//` ↔ `%`, `NOT AND OR
   GT LT GE LE NG NL NE CAT PT` ↔ the operators, matching the OCR fragment
   `, .` that appears in the scan at this position.
3. The 12 letter sequences `NOT AND OR GT LT GE LE NG NL NE CAT PT` are
   reserved words: no identifier may finally be replaced by any of them.
   *Cross-check:* C28-8201-1 — "Certain identifiers of the 48-character set
   cannot be used as programmer-defined identifiers…: GT, GE, NE, LT, NG, LE,
   NL, CAT, OR, AND, NOT, and PT" — the same twelve.
4. In the final text, each colon `:` is to be replaced by two periods `..`;
   when it immediately follows a period the replacement must be preceded by a
   blank (so that `A.B:` becomes `A.B ..`, not `A.B...`).
   *Cross-check:* the two replacement production rules are lost in the OCR, but
   C28-8201-1 states the rule directly — "The two periods that replace the
   colon must be immediately preceded by a blank if the preceding character is
   a period" — which is exactly the (a)/(b) case split the report prints.
   The same source gives the analogous rule for the `%` → `//` substitution of
   rule 1 (a blank is required next to an adjacent asterisk, to avoid forming
   `/*` or `*/`).

## 4. Concrete syntax (report §3)

### 4.1 Higher level production rules (§3.1)

```
(1)  program ::= procedure•••

(2)  procedure ::= [ prefixlist ] entry-namelist PROCEDURE
                   [ ( parameterlist ) ] [ procedure-optionslist ] sentencelist

(3)  entry-namelist ::= ( {,• identifier•••} )

(4)  parameterlist ::= ( [ {,• identifier•••} ] )

(5)  procedure-optionslist ::=
       ( { function-attribute | RECURSIVE | OPTIONS ( {,• external-option•••} ) }••• )

(6)  sentencelist ::= [ sentence••• ] end-clause

(7)  end-clause ::= [ prefixlist ] [ labellist ] END ;

(8)  sentence ::= statement | procedure | entry | declaration-sentence | format-sentence
```

#### 4.1.1 Declarations (§3.1.1)

```
(9)   declaration-sentence ::= [ labellist ] DECLARE declarationlist ;

(10)  declarationlist ::= ( {,• declaration•••} )

(11)  declaration ::= [ integer ] ( identifier | ( declarationlist ) )
                      [ dimension-attribute ] [ attribute••• ]

(12)  dimension-attribute ::= ( {,• bound-pair•••} )

(13)  bound-pair ::= [ expression ] expression | *
```

⚠ (13) OCR reads `[expression] expression | •`; the `| *` alternative (asterisk bound) is inferred from the `*`/`•` OCR confusion seen elsewhere. *Cross-check:* Y33-6003-0 says parameter bounds are "specified by asterisks" and cross-sections use asterisk subscripts, supporting the `| *` reading. May also read `{ expression | * }` in the position shown.

⚠ (112)/(113)/(114) **reinterpreted in this pass.** The scan of this page is
short in (113) and over-long in (114): the visible options of (113) are only
FILE, IGNORE, KEYTO, NOLOCK, while the lines scanned under (114) contain
`INTO ( reference )`, `KEY ( expression )`, `SET ( reference )`,
`FROM ( reference )`, `KEYFROM ( expression )` and `EVENT ( reference )` —
which are **record-I/O options, not DISPLAY options**, in every contemporaneous
document:

- Y33-6003-0's record-transmission statements use exactly FILE, INTO, KEYTO,
  IGNORE, SET, KEY, FROM, KEYFROM, EVENT, NOLOCK (e.g.
  `READ FILE (filename) INTO (variable) [KEYTO (…)] [EVENT (…)]`,
  `WRITE FILE (filename) FROM (variable) KEYFROM (expression)`,
  `LOCATE variable FILE (filename) [SET (…)] [KEYFROM (…)]`).
- DISPLAY takes no such options in any version: C28-6571-3 (1966) prints
  `DISPLAY (scalar-expression);`, and Y33-6003-0 prints
  `DISPLAY (scalar-expression);` or
  `DISPLAY (scalar-expression) REPLY (scalar-character-variable) [EVENT (…)];`
  with the syntax rule "REPLY and EVENT may appear in either order".

The most probable explanation is a two-column page whose second column was
interleaved into the following rule by the scanner. Rule (114) above is
therefore given in its attested form (with REPLY/EVENT permutable), and the
stray option lines are recorded here as belonging to (113). Rule (113) is left
as scanned rather than silently extended; an implementation should take the
option set from Y33-6003-0 and record the divergence (this is what
`docs/IMPLEMENTATION-PLAN.md` milestone M7 does).

`A B C D E G H I K M P S T V y Z $ . , * / 1 2 3 6 8 9`, and *every one of them*

  characters 1, 2, and 3");

  associated position contains the shilling character s", `M` "the start of a
  field", `P` the pence character, and the pence/shilling digit specifiers

  (shillings field) — cf. "The Z picture character is not allowed to the right

Restored from the attested set but not visible in the scan: `X Y F R + - 7`

*not* 1968 picture characters and are correctly absent).
